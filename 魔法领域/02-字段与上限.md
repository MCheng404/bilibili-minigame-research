## 3. 危险字段（已评估但不建议改）

| 字段 | 风险 | 源码依据 |
|---|---|---|
| `outCampLevel` | 越界必崩 | `for(let e=0;e<=g.playerInfo.outCampLevel;e++){let t=a.treeCfg[e], i=t.mValue.split("_")...}` —— 这里没有 break，`treeCfg[e]` 为 undefined 时 `.mValue` 直接抛异常 |
| `outHeroList[].isUnlock` | 破坏引导流程 | 与 `newGuideStep_new` 联动，`showGuide()` 里按 `level<5 / <6` 分阶段推进 |
| `maxChapterId` | 引动关卡掉落配置 | 结算处 `t.chapterId == g.playerInfo.maxChapterId` 决定额外掉落 |
| `sVersion` | 存档失效 | `login()` 里 `s.sVersion == e` 才复用存档，不匹配会**新建存档覆盖** |
| `lastSaveTime` / `lastLoginTime` / `lastAfkBaseTime` | 离线收益计算错乱 | 用 `gg.platform.serverTime - lastSaveTime` 算离线时长 |
| `outSkillList` | 结构复杂，字段不明 | 初始化时 `outSkillList.push({id:99999})`，其余字段需逆向 |

## 4. 上限配置表位置

| 配置 | 路径 | 用途 |
|---|---|---|
| `powerCfg` | `a.powerCfg` （`JSON.parse(...)[0]`，是对象不是数组） | `.max` 体力上限、`.consume` 开局消耗、`.value` 恢复量、`.cd` 恢复间隔（分钟） |
| `roleUpgradeCfg` | `a.roleUpgradeCfg`（数组） | 按 `.lv` 索引，`.fragment` 升星碎片 |
| `hero_upCost` | `a.hero_upCost`（数组） | 按 `.level` 索引，`.slice` 升级消耗 |
| `vipCfg` | `a.vipCfg`（数组） | 按 `.vipLv` 索引；`length-1` 即最高等级 |
| `treeCfg` | `a.treeCfg`（数组） | 营地/科技树，`.mValue` / `.cValue` 效果值 |
| `heroCfg` | `a.heroCfg`（数组） | 字段：`id / icon / name / job / jobIcon / kind / atk / def / str / int / talent / upValue1 / upValue2 / spineRes` |
| `talentCfg` | `a.talentCfg`（数组） | 天赋配置 |

通用取上限写法：

```js
function cfgMax(table, key) {
  var m = 0;
  for (var i = 0; i < table.length; i++) {
    var v = table[i][key];
    if (typeof v === 'number' && v > m) m = v;
  }
  return m;
}
```

> 不要用 `table.length - 1` 代替 `cfgMax(table, 'lv')`——配置表的 `lv` 不一定
> 从 1 连续递增，也不一定等于 `length`。

## 5. 广告与存档

### 5.1 广告接管

游戏自己包了一层 `playVideo` 并保留原始版：

```js
let e = gg.platform.playVideo;
gg.platform.realPlayVideo = e;
gg.platform.playVideo = function(e){ return new Promise(...) }
```

以及"跳过广告"判断：

```js
gg.platform.playVideo_pre = function () {
  ...
  return !gg.platform.config.videoId ||
    (g.playerInfo.freeVideoNum > 0
      ? (g.playerInfo.freeVideoNum--, Laya.stage.event(t.ShowTip, "免广次数还剩余..."), true)
      : ...)
}
```

接管方式（两个都要，游戏会重设，需要每轮检查标记重新接管）：

```js
playVideo_pre = () => true;
playVideo     = () => new Promise(r => setTimeout(() => r(1), 30));
```

调用方普遍是 `playVideo(...).then(e => { if (e > 0) 发奖励 })`，
返回 `1` 即视为看完。

## 6. 战斗内数据（battleSave）

战斗数据不在 `playerInfo` 顶层，而是战斗中创建的 `playerInfo.battleSave`，
退出战斗即销毁。所以它是**只在战斗中存在**的修改目标。

### 6.1 结构

```js
battleSave = {
  goldNow: 0,                 // 局内金币，商店买东西用
  roleLimitNum: 6,            // 上阵数量上限（UI 显示 "已上阵/上限"）
  heroSaveInfo: {
    heroId, level, talentList: [],
    mp_now: 50 + 5*int,       // 法力
    mp_max: 50 + 5*int,
    atk, def, str, int,
    lck: 0, mor: 0, spd: 0
  },
  roleList: [ { roleId, num, posX, posY, isUp } ],
  pagePathSelect, chapterId, chapterId_child,
  reliveTime, changeCount, ...
}
```

### 6.2 单位血量与数量的联动（关键）

战斗单位是挂在显示节点上的 Laya Script，字段为：

| 字段 | 含义 |
|---|---|
| `life_per` | 单个单位的血量 |
| `life_max` | 总血量上限 = 数量 × `life_per` |
| `life_now` | 当前总血量 |
| `roleNum` | 剩余单位数量 |
| `roleNum_init` | 初始单位数量 |
| `teamId` | **0 = 我方，1 = 敌方** |

受击结算时游戏自己重算数量：

```js
this.beAtkRole.roleNum = Math.ceil(this.beAtkRole.life_now / this.beAtkRole.life_per);
this.beAtkRole.life_max = this.beAtkRole.roleNum * this.beAtkRole.life_per;
```

**所以「血量」和「人数」是同一套机制**——掉血就等于掉人。想要血量不掉、人数不减，
必须同时做两件事：

1. `life_per` 放大（本项目用 ×50，并打 `__hmBoost` 标记防重复放大）
2. `life_now = life_max = roleNum_init × life_per`，把 `roleNum` 复位到 `roleNum_init`

只补 `life_now` 不放大 `life_per` 的话，一旦遭遇超过总血量的单次伤害，
单位会被直接判定死亡移除，之后再补也补不回来。

### 6.3 定位单位对象

单位不是显示节点本身，而是挂在节点的 `_components` 数组里的 Script。
遍历 `Laya.stage` 整棵树，对每个节点的 `_components` 检查是否同时具备
`life_now` / `life_max` / `life_per` 三个 number 字段即可识别：

```js
function eachUnit(fn) {
  var stage = Laya.stage, stack = [stage], guard = 0;
  while (stack.length && guard++ < 6000) {
    var node = stack.pop();
    try {
      var cs = node._components;
      if (cs) for (var i = 0; i < cs.length; i++) {
        var c = cs[i];
        if (c && typeof c.life_now === 'number'
             && typeof c.life_max === 'number'
             && typeof c.life_per === 'number') fn(c);
      }
    } catch (e) {}
    try {
      var k = node.numChildren | 0;
      for (var j = 0; j < k; j++) stack.push(node.getChildAt(j));
    } catch (e) {}
  }
}
```

加 `guard` 上限是必须的——显示树在战斗中会增删节点，万一出现环引用不会死循环。

### 6.4 当前启用的战斗强化

| 目标 | 写入值 | 位置 |
|---|---|---|
| 局内金币 | 999999 | `battleSave.goldNow` |
| 上阵上限 | 20 | `battleSave.roleLimitNum` |
| 英雄法力 | 9999 / 9999 | `battleSave.heroSaveInfo.mp_max / mp_now` |
| 英雄四维 | 9999 | `battleSave.heroSaveInfo.atk / def / str / int` |
| 我方血量 | `roleNum_init × life_per × 50` | 单位对象 |
| 我方人数 | 复位到 `roleNum_init` | 单位对象 `roleNum` |

刷新频率：**500ms** 一次。主循环是 2.5s，太慢——一次暴击就可能把单位打空，
所以战斗强化单独跑一个快循环，只在 `battleSave` 非空时工作。

> 注意 `heroSaveInfo` 在开战时从养成数据复制，所以养成侧的
> `outHeroList[].atk` 改了不会自动同步到已在进行的战斗里，需要单独写这份。

## 7. 游戏倍速（Laya.timer.scale）

### 7.1 原生机制

游戏有两个硬编码的配置值：

```js
a.gameSpeed_normal = 1.31   // "1x" 挡
a.gameSpeed_double = 1.62   // "2x" 挡
```

战斗开始（`click_fight`）时按开关选一个：

```js
g.playerInfo.setting_doubleSpd
  ? (Laya.timer.scale = a.gameSpeed_double, btn_speed.skin = "game/img_speed_2.png")
  : (Laya.timer.scale = a.gameSpeed_normal, btn_speed.skin = "game/img_speed_1.png")
```

游戏内加速按钮（`onClickChangeSpeed`）切换 `setting_doubleSpd` 布尔值，
然后按同样逻辑设 `Laya.timer.scale`。战斗结束时 `Laya.timer.scale = 1`。

### 7.2 修改方法

**把 `a.gameSpeed_normal` 和 `a.gameSpeed_double` 两个值都改成目标挡位**，
这样游戏自己所有重设路径都会落到同一个值：

```js
G.__hma.gameSpeed_normal = 3;
G.__hma.gameSpeed_double = 3;
g.playerInfo.setting_doubleSpd = true;
Laya.timer.scale = 3;
```

即使玩家点游戏内加速按钮触发 `onClickChangeSpeed`，toggle 后取的还是我们的值。

另外在战斗循环（500ms）里强制回写 `Laya.timer.scale`，防止被 Tween 动画、
结算等处临时设的 `scale=1` 覆盖。

### 7.3 挡位定义

| 挡位 | Laya.timer.scale | 说明 |
|---|---|---|
| 1x | 1.31 | 游戏原速 |
| 2x | 1.62 | 游戏原倍速 |
| 3x | 3 | 新增 |
| 4x | 4 | 新增 |

## 8. 三选一场景的次数限制

战斗结束（以及章节推进）时会弹出 `page/Game_ChooseRole.scene`，提供三张兵种卡
让玩家三选一，另外有两个按钮：

| 按钮 | 作用 | 次数来源 |
|---|---|---|
| `btn_change`（换一批） | 重掷三张卡 | `battleSave.freeRefCount` / `freeChangeNum` / `videoRefCount` |
| `btn_getAll`（全都要） | 一次性领取全部 3 个 | `battleSave.getallCount` |

### 8.1 "全都要只能用一次"的根因

只有三处涉及 `getallCount`：

```js
// 1) 战斗初始化 —— 限制来源
s.getallCount = 1;

// 2) 按钮显示条件
g.playerInfo.battleSave.getallCount > 0 && (this.btn_getAll.visible = true, ...)

// 3) 点击消耗
clickGetAll() {
  ...
  gg.platform.playVideo("全都要").then(e => {
    if (e > 0) {
      g.playerInfo.battleSave.getallCount--;          // 消耗一次
      for (let e = 0; e < 3; e++) this.clickChoose(e); // 三个全领
      this.close();
    }
  })
}
```

所以"每场战斗只能点一次全都要"，根源就是初始化时写死的 `getallCount = 1`。

### 8.2 修改方法

在战斗循环里维持一个正值即可 —— 按钮显示条件只看 `> 0`，用掉后循环会补回来：

```js
if (SET.getallNum > 0) {
  b.getallCount = SET.getallNum;   // 默认 999
}
```

战斗场景重建 `battleSave` 时会被游戏重新赋回 1，500ms 循环再拉起来，所以
**每场战斗的每一次三选一弹窗都能点「全都要」**，三个兵种全部收入囊中。

「换一批」的免费次数是同一套机制，改 `b.freeRefCount` 即可。

### 8.3 与免广告的关系

`clickGetAll` 和 `clickChange` 都先调 `gg.platform.playVideo(...)`。
免广告接管（`playVideo` 直接 resolve 1 / `playVideo_pre` 恒 true）让这两个按钮
**瞬间生效**，无需真的看广告。

## 9. 复活机制

### 9.1 次数来源链

复活次数**不是直接存在 playerInfo 里**，而是从 VIP 特权表推导出来的：

```js
// getVipPrivilege(e) 读的是 vipCfg 里「当前 VIP 等级」那一项的 privilege_<e>
static getVipPrivilege(e) {
  if (this.playerInfo) {
    let t = a.vipCfg.find(e => e.vipLv == this.playerInfo.vipLv);
    if (t && null != t["privilege_" + e]) return t["privilege_" + e];
  }
  return 0;
}
```

`privilege_3` 在 VIP 界面上的文案是「主线副本中，可用复活次数」。

三处用到它：

```js
// 1) 战斗初始化 —— 决定本场战斗有几次复活
s.reliveTime = g.getVipPrivilege(3);

// 2) 阵亡判定
i.reliveTime > 0
  ? (i.reliveTime--, Laya.Scene.open("page/Game_Relive.scene"))
  : Laya.Scene.open("page/Game_Over.scene");

// 3) 阵亡埋点（统计用）
Frequency: g.getVipPrivilege(3) - g.playerInfo.battleSave.reliveTime + 1
```

### 9.2 复活界面

`page/Game_Relive.scene`（类 `De`）只有两个按钮：

| 按钮 | 行为 |
|---|---|
| `btn_video` | `gg.platform.playVideo("复活")` → 成功则 `Laya.stage.event(t.GameRelive)` → `onGameRelive()` 重新布阵复活 |
| `btn_continue` | 直接开 `Game_Over.scene`（放弃，结算） |

`onGameRelive()` 会清空 `box_2d` 的所有单位、把 `gameStat` 重置为 `Game_Prepare`，
再按 `chapterId_child` 重建部队，等于重开本场战斗。

### 9.3 修改方法

改 **VIP 特权表**最彻底 —— 初始值和消耗上限一起变：

```js
var cfg = G.__hma.vipCfg;
for (var i = 0; i < cfg.length; i++) cfg[i].privilege_3 = 999;
```

> ⚠️ `vipCfg` 是**远程配置**，`InitGameTable` 里
> `case "vip": this.vipCfg = JSON.parse(e[t].value)` 会整体替换掉这个数组。
> 所以补丁必须**周期性重打**（本项目在 500ms 循环里做），不能只打一次。

同时在 `battleSave` 里也保一份底：

```js
if (b.reliveTime < n) b.reliveTime = n;
```

免广告接管让 `playVideo("复活")` 直接 resolve 1，
所以复活界面点「看广告复活」是**瞬间生效**的，不用真看广告。
