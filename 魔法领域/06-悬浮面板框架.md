# 06 · 悬浮面板框架（跨游戏共用）

游戏内悬浮修改器是一套**与具体游戏无关的通用框架**。
新增一款小游戏时，只需要写「游戏适配层」（布局配置 + 数值写入函数），
框架代码一行都不用改。

源码：`src/nativelib/ui_block.js`（框架本体）+ `src/nativelib/inj.js`（游戏适配层）

## 3. 布局描述 API

游戏适配层提供 `G.__hmLayout`，框架按它渲染：

```js
G.__hmLayout = {
  sections: [{
    title: '冒险数值',
    rows: [
      { t:'num',  label:'钻石', key:'diamond', apply(v){ ... } },
      { t:'num',  label:'VIP 等级', key:'vip', apply(v){ ... } },
      { t:'gear', label:'游戏倍速', key:'speed',
        opts:[ {label:'1x',value:1.31}, {label:'2x',value:1.62},
               {label:'3x',value:3},    {label:'4x',value:4} ],
        apply(v){ ... } },
      { t:'sw',   half:true, label:'无限金币', key:'btGold' },
      { t:'sw',   label:'免广告', key:'adFree', onChange(on){ ... } }
    ]
  }],
  actions: [
    { label:'一键拉满', color:'#2456B8', fn(){ ... } },
    { label:'写入存档', color:'#1F7A4D', fn(){ ... } }
  ]
};
```

| 行类型 | 必填 | 可选 | 说明 |
|---|---|---|---|
| `num` | `label` `key` | `apply(v)` | 输入框 + 「应用」按钮 |
| `sw` | `label` `key` | `onChange(on)`, `half:true` | 开关；`half` 表示半宽两列并排 |
| `gear` | `label` `key` `opts` | `apply(v)` | 多挡位分段选择器 |

数值与开关的当前值放在 `G.__hmSet`（挂 `globalThis`，面板重建/切场景都不丢）：

```js
G.__hmSet = {
  diamond: 888888,  wood: 99999,  ...
  speed: 1.62,      // 当前挡位
  btGold: true,     // 开关状态
};
```

**接入新游戏的最小工作量**：

1. 写 `G.__hmSet`（默认值）
2. 写 `G.__hmLayout`（要显示哪些项）
3. 写 `__hmApply` / `__hmApplyHeroes` / `__hmBattle` 等写入函数
4. 在 `__hmLayout` 的 `apply` 里调用它们

框架部分（`ui_block.js`）完全复用。

## 4. 圆角怎么实现

Laya 的 `graphics.drawRect` **不支持圆角**，必须用 `graphics.drawPath`：

```js
sp.graphics.drawPath(0, 0, [
  'moveTo', x+r, y,
  'lineTo', x+w-r, y,
  'arcTo', x+w, y, x+w, y+r, r,
  'lineTo', x+w, y+h-r,
  'arcTo', x+w, y+h, x+w-r, y+h, r,
  'lineTo', x+r, y+h,
  'arcTo', x, y+h, x, y+h-r, r,
  'lineTo', x, y+r,
  'arcTo', x, y, x+r, y, r,
  'closePath'
], fillColor, lineColor, lineWidth);
```

三种路径变体：

| 函数 | 用于 |
|---|---|
| `rrPath` | 完整圆角矩形（面板、输入框、按钮、挡位） |
| `rrTopPath` | 仅上方两角圆角（标题栏，与面板圆角对齐） |
| `rrBottomPath` | 仅下方两角圆角（底部栏） |

**兼容性**：探针启动时会实际调用一次 `drawPath` 做自检，结果记在 `G.__hmHasPath`，
并输出到探针回读字段 `R.path`。若引擎不支持，会自动降级为直角矩形，不会白屏。

## 5. 三个真实踩过的坑

### 5.1 参数遮蔽 → 按钮被画成 0 高度

```js
function mkBtn(parent, label, x, y, w, h, ...) {
  function paint(h) {                        // ← h 遮蔽了外层的按钮高度 h
    drawRR(sp, 0, 0, w, h, R_CTRL, h ? hover : base, border, 2);
  }
  paint(0);                                  // 传进来的是悬浮标志 0/1
}
```

结果：按钮高度变成 0 或 1，只剩一条边线。
**修法**：悬浮标志参数改名 `hv`，绝不与尺寸参数同名。

### 5.2 `var` 闭包共享 → 所有「应用」按钮都改最后一行

```js
for (var ri = 0; ri < sec.rows.length; ri++) {
  var row = sec.rows[ri];
  var inp = mkInput(...);                    // var 是函数作用域
  mkBtn(..., function () { parseInt(inp.text) });  // 闭包捕获的是变量，不是值
}
```

所有轮次共享同一个 `row` / `inp`，循环结束后它们指向**最后一行**，
于是点任何一个「应用」都会读写最后那个输入框。开关行和挡位行的回调同样串行。

**修法**：每轮用 IIFE 包住，把 `row` 作为参数传进去：

```js
for (var ri = 0; ri < sec.rows.length; ri++) {
  (function (row) {
    var inp = mkInput(...);
    mkBtn(..., function () { parseInt(inp.text); });
  })(sec.rows[ri]);
}
```

回归测试见 `src/test_visual.js` 的「每行独立写入」用例（11 行各自验证）。

### 5.3 补丁锚点漂移 → 代码块被插入两份

早期 `patch_ui.py` 用 `function refreshTop()` 作为替换起点。
后来新块内部也出现了 `refreshTop()`（它在 `THEME` 之后），
第二次执行时锚点命中了块**内部**，导致主题部分被重复保留 —— 文件里出现两份 `THEME`。

**修法**：改用显式哨兵标记，替换变成幂等：

```python
START = '// ===== HM UI BLOCK START ====='
END   = '// ===== HM UI BLOCK END ====='
```

`patch_ui.py` 每次执行后校验 `THEME` 出现次数必须为 1。

## 6. 预览渲染器（改 UI 不用开游戏）

`src/render_panel.js` 用 mock 环境跑一遍真实的面板构建，
把 Laya 的绘制调用（`drawPath` / `drawRect` / `drawCircle` / 文本）
翻译成 SVG，输出与游戏内**所见一致**的预览图。

```bash
node render_panel.js panel_preview.svg
```

Laya `arcTo(x1,y1,x2,y2,r)` → SVG `A` 的换算规则：

- 圆心 `O = P + r * n`，`n` 为入射方向右转 90° 的法线（指向图形内部）
- 本框架所有圆角都是顺时针，SVG `sweep-flag = 1`
- 出射方向 = `(E - O)` 右转 90°

> 这个预览器抓到了 5.1 的 0 高度按钮 bug —— 纯靠读代码不容易发现。
