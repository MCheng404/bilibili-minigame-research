# 04 · 踩坑记录

这份记录比前几份更重要——它记录的是**不该走的路**和**误判的判据**，
能省掉后来者大量时间。

格式：现象 → 当时的误判 → 真相 → 修法。

---

## A. 方向性错误（最浪费时间的一类）

### A1. 在内存扫描上纠缠

**现象**：搜 `11799` 得到几十条候选，改掉后界面确实变了；但再搜新值变成
0 条匹配，或者切个界面就变回原值。

**误判**：以为是"安卓 16/17 封杀了内存修改"。

**真相**：跟系统版本无关。改到的是**副本**（序列化的存档字符串、`String(n)`
临时串、显示层 `text` 字段、JIT 常量折叠结果）。真值在 V8 堆里的 JS 对象上，
下一帧会从源对象重新算出来覆盖掉。

**教训**：这类游戏在拿到源对象前，内存扫描本质不可行。所有围绕地址重建、
候选清扫、双精度通道、Smi 编码的工作全部无效。

### A2. 对象图 BFS

**现象**：已能执行任意 JS，从 `Laya.stage` + 所有 `_components` 做 BFS，
遍历 **55,921** 个对象、深度 8，`hi: 0`（一个都没命中）。

**真相**：`g` 是内层 IIFE 作用域的 `class` 声明，**根本不在可达图上**。
不是藏得深，是不在。

**教训**：JS 语言层面没有任何反射手段能枚举函数闭包变量（`[[Scope]]` 是内部槽）。
BFS 只对"挂在 UI/组件树上的数据"有效。

### A3. 靠改 HTML / JS 资源文件

**现象**：改了 `game.js`、`shell.html` 埋 `throw`，游戏照样进。

**真相**：容器根本不执行这些文件。真正执行的是引擎从分包里加载的 bundle。

**判据**：埋 `throw` 后游戏仍能正常进入 → 该文件不是执行入口。

## B. 工具与运行时

### B4. frida 在 `:web` 进程必崩

**现象**：`libfrida_gadget.so` 一加载，游戏进程直接退出。改成中性文件名
（`libhmshim.so`）也一样。

**真相**：冲突在 frida 运行时本身，不在名字。

**修法**：自研十几 KB 的 `.so` 做 inline hook，完全够用。

### B5. `dlopen` 按 soname 查符号失败

**现象**：`dlopen("libMiniEngine.so")` 返回 null。

**真相**：引擎是按**绝对路径**加载的，按 soname 查不到。

**修法**：读 `/proc/self/maps` 拿 `offset==0` 的第一段作为基址，
再解析磁盘上同一份 `.so` 的 `.dynsym`，`运行地址 = base + st_value`。
注意同一 `.so` 会出现在多段里，要按 path 再校验一次。

### B6. `Function::Call` 热路径 hook 导致卡退

**现象**：挂上 `v8::Function::Call` 后游戏运行几秒就崩。

**真相**：每帧几百上千次调用，hook 开销太大。

**修法**：只 hook `Script::Compile`。它调用频率低，且正是我们需要改源码的唯一入口。
（代码里保留了 `if (0 && !orig_func_call)` 关闭它。）

## C. 注入链路

### C7. `inject N: no script` —— 注入 JS 少一个花括号

**现象**：日志全是 `inject 0: no script`，探针完全没跑，但看不出哪错了。

**真相**：注入 JS 少一个闭合 `}`，`Script::Compile` 直接返回 NULL。
`MaybeLocal<Script>` 为空时日志只会显示 `no script`，**不报具体位置**。

**修法**：
1. 探针写成独立 `.js` 文件，`node --check` 过一遍
2. 用 `build_inj.py` 自动转 C 字符串，不手写转义
3. 写个括号平衡扫描脚本（统计 `{` / `}` 深度，最后应为 0）

```python
s = open('_inj_check.js', encoding='utf-8').read()
d = 0; q = None; i = 0
while i < len(s):
    c = s[i]
    if q:
        if c == '\\': i += 2; continue
        if c == q: q = None
    else:
        if c in ('"', "'"): q = c
        elif c == '{': d += 1
        elif c == '}': d -= 1
    i += 1
print('end depth', d)    # 必须是 0
```

### C8. 热更判重导致新库不生效

**现象**：改了 `.so`、推上去、重启进程，日志行为完全没变。

**真相**：加载器判重是 `!dst.isFile() || dst.length() != src.length()`。
改动只差一两个字符时**文件大小完全相同**，条件不成立，新库没被拷进去。

**修法**：部署时永远先 `rm -f` 掉 `data/data/.../files/libhmshim.so`。

### C9. 注入到了临时 context

**现象**：注入日志全 `ok`，但回读没有任何数据。

**真相**：引擎会创建多个 V8 context（引擎初始化、临时脚本各一个）。
探针的 `setInterval` 若挂在临时 context 上，context 一销毁定时器就停了。

**修法**：源码改写命中的那个 context 就是游戏主 context，此时把它在去重表里
的记录作废，重新注入一次：

```c
if (ps) {
    src = ps;
    for (int i = 0; i < g_seq && i < 40; i++) {
        if (g_inj_ctx[i] == ctx) g_inj_ctx[i] = NULL;
    }
}
```

### C10. 依赖 `setTimeout` 做首次执行

**现象**：同 C9，或者游戏进了但面板要等几秒才出现。

**修法**：探针编译后**立即执行一次** `__hmdump()`，不依赖定时器。
定时器只负责后续刷新。

## D. 面板相关

### D11. 悬浮窗越叠越多

**现象**：屏幕上出现好几个一模一样的面板。

**真相**：去重检查写的是 `stage.getChildByName('hmRoot')`，
但实际创建的对象 `name` 是 `hmBody` / `hmMini`。检查永远返回 null，
每 2.5 秒循环就重建一份。

**修法**：按真实名字收集，保留一份、多余的直接 `removeChild`；
只找到一半说明残缺，全清后重建。

```js
if (n === 'hmBody') { if (body) extra.push(c); else body = c; }
```

**教训**：凡是用 `name` 做唯一键的地方，创建和查找必须用同一个常量。
最好定义 `var N_BODY = 'hmBody'` 两边共用。

### D12. 面板挡住右上角按钮

**修法**：
1. 默认折叠成 `84×34` 小条
2. 折叠条默认放右侧中部而非右上角
3. 标题栏和小条都能拖，位置用 `G.__hmPosX/__hmPosY` 记住，重建时恢复

## E. 字符串处理

### E13. `charCodeAt` 截断中文

**现象**：回读的 JSON 里中文全变乱码或直接解析失败。

**修法**：`'TAG|' + encodeURIComponent(JSON.stringify(obj))`。
中文经 URI 编码后是纯 ASCII，逐字符 `charCodeAt` 才安全。

### E14. C 字符串里的 `\n` 破坏 JS

**现象**：注入 JS 报语法错。

**真相**：C 的 `"\n"` 在 JS 里是真实换行，如果落在 JS 字符串字面量中间就会断开。

**修法**：JS 里需要换行符时用 `String.fromCharCode(10)`；
C 侧生成时用 `build_inj.py` 逐行转换，天然不会产生裸换行。

### E15. `endsWith("</html>")` 因尾部换行永不成立

**现象**：HTML 探测逻辑一直不命中。

**真相**：字符串尾部有 `\n`，`endsWith("</html>")` 永远 false。

**修法**：先 `trim()` 再判断。

## F. 业务逻辑（配置表无空值保护）

这类问题最危险——不改就没事，一改就崩，而且报错信息在 logcat 里往往看不到。

### F16. 所有"等级"字段必须从配置取上限

源码里的典型写法：

```js
a.vipCfg.find(t => t.vipLv == e).vipLv                      // getVipValid
a.roleUpgradeCfg.find(e => e.lv == t.level).fragment        // checkStatus
a.hero_upCost.find(e => e.level == this.selectHeroData.level).slice   // 升级
```

`find()` 找不到返回 `undefined`，紧接着取字段就是 `TypeError`。

**修法**：

```js
function cfgMax(table, key) {
  var m = 0;
  for (var i = 0; i < table.length; i++) {
    var v = table[i][key];
    if (typeof v === 'number' && v > m) m = v;
  }
  return m;
}
// 兵种
P.outCampInfo[i].level = cfgMax(a.roleUpgradeCfg, 'lv');
// 英雄
P.outHeroList[i].level = cfgMax(a.hero_upCost, 'level');
// VIP
P.vipLv = Math.min(10, a.vipCfg.length - 1);
```

**不要用 `table.length - 1` 代替 `cfgMax(table, key)`** —— 配置表的 `lv`
不一定从 1 连续递增，也不一定等于 `length`。

### F17. 数组字段不要整体赋值

**现象**：`campCoinNum` 改成 `[99999,...]` 后立刻被重置。

**真相**：整体替换后，后续流程仍在操作旧引用，或者新数组长度/类型不匹配。

**修法**：逐项写 `for (i) arr[i] = 99999;`

### F18. 神格小数位有硬约束

```js
if (g.playerInfo.godExp >= e)
  if (g.playerInfo.godExp -= e, g.playerInfo.godLevel_small++,
      g.playerInfo.godLevel_small >= 6) {
    g.playerInfo.godLevel_small = 0;
    g.playerInfo.godLevel_big++;
    ...
  }
```

`godLevel_small` 累计到 6 会自动归零并进位 `big+1`。
所以 **`small` 的合法区间是 0..5**，写 6 及以上会被游戏自己纠正，
写 `5` 是稳定最大状态。

### F19. 营地等级越界必崩

```js
for (let e = 0; e <= g.playerInfo.outCampLevel; e++) {
  let t = a.treeCfg[e],           // ← 越界返回 undefined
      i = t.mValue.split("_"),    // ← TypeError
      n = t.cValue.split("_");
```

注意**另一处**有 `if (i.id > g.playerInfo.outCampLevel) break;` 保护，
但上面这处没有。所以 `outCampLevel` 不能随便写大。

## G. 环境与命令

### G20. `MSYS_NO_PATHCONV` 只对参数生效

**现象**：`adb push lib.so /data/local/tmp/x.so` 报
`remote secure_mkdirs() failed`——Git Bash 把 `/data/local/tmp`
当成本地路径转换成了 `E:/CLI/Programs/Git/data/local/tmp`。

**修法**：命令前加 `MSYS_NO_PATHCONV=1`。

**但这个变量管不了 `$(...)`**：

```bash
# ❌ 错：$(pidof ...) 由本地 bash 展开 → command not found
adb shell "su -c 'kill -9 $(pidof tv.danmaku.bili:web)'"

# ✅ 对：先取 PID 再传入
PID=$(adb shell pidof 'tv.danmaku.bili:web' | tr -d '\r')
adb shell "su -c 'kill -9 $PID'"
```

### G21. 管道会挂住 daemon 类命令

如果设备上有 agent-browser 之类的常驻 daemon，`cmd | tail` 会因为
daemon 继承了 stdout 管道句柄、`tail` 等不到 EOF 而无限挂起
（命令其实早执行完了）。这类命令不要接管道，重定向到文件或直接看输出。

## H. 排查顺序建议

遇到"改了没反应"，按这个顺序查，能最快定位：

```
1. logcat 有没有 HMShim 日志？
   ├─ 没有 → .so 没加载：检查 LSPosed 模块是否启用、进程是否重启
   └─ 有 → 继续

2. 有没有 "source patched"？
   ├─ 没有 → 源码改写没命中：检查关键字、g_patch_done 是否已被占用
   └─ 有 → 继续

3. 有没有 "inject N ok"？
   ├─ "no script" → 注入 JS 语法错误，跑 node --check
   └─ ok → 继续

4. readtag 能读到数据吗？
   ├─ 无数据 → 注入到了临时 context，或探针没立即执行
   └─ 有数据 → 看具体字段

5. gok / aok / ad 是 1 吗？
   ├─ gok=0 → 改写里暴露的标识符名不对
   └─ 都是 1 → 数值逻辑问题，看 mock 测试
```
