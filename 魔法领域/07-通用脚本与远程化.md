# 07 · 通用脚本与远程化机制

这一篇讲三件事：**通用脚本**（未适配游戏的基础去广告）、
**运行时脚本加载**（改脚本不用重编译 .so）、**App 拉取仓库**（新增游戏不用更新 App）。

---

## 1. 三层架构

```
┌──────────────────────────────────────────────────────────┐
│ native 层  libhmshim.so                                   │
│  · 定位 libMiniEngine.so，hook v8::Script::Compile         │
│  · 改写 bundle 源码（暴露单例 + 插入桥接函数）              │
│  · 运行时从磁盘读注入脚本，编译并执行                       │
└────────────────────┬─────────────────────────────────────┘
                     │ 注入 inj.js
┌────────────────────▼─────────────────────────────────────┐
│ 通用层  nativelib/common.js                                │
│  · 免广告（桥接平台对象 + 扫描 globalThis）                │
│  · 通用模式面板（去广告 / 接管强度 / 重新接管）             │
│  · 与具体游戏完全无关，任何 Laya 小游戏都能用               │
└────────────────────┬─────────────────────────────────────┘
                     │ 检测到 __hmg 后启用
┌────────────────────▼─────────────────────────────────────┐
│ 适配层  nativelib/inj.js                                   │
│  · 数值修改（养成 / 战斗 / 倍速 / 复活 / 三选一）           │
│  · 适配模式的完整面板                                     │
└──────────────────────────────────────────────────────────┘
```

`common.js` 写成**独立可 eval 的 IIFE**，构建时内联进 `inj.js`，
两种形态共用同一份源码，不会出现「两份代码不同步」。

## 2. 通用脚本：未适配游戏的基础去广告

### 2.1 为什么要「桥接」

游戏的平台对象（`gg.platform`）通常是**模块闭包里的私有变量**，
从 `globalThis` 上根本拿不到。BFS 扫遍整个对象图也找不到。

但我们能改写 bundle 源码，而改写后的代码**运行在模块作用域内** ——
所以可以在那里定义一个函数，让它作为「桥」把私有变量递出来：

```js
;try{globalThis.__hmBridge=function(){var o={}
  try{o.gg=(typeof gg!=='undefined'?gg:null)}catch(e){}
  try{o.a =(typeof a !=='undefined'?a  :null)}catch(e){}
  try{o.g =(typeof g !=='undefined'?g  :null)}catch(e){}
  try{o.cfg=(typeof config!=='undefined'?config:null)}catch(e){}
  return o}}catch(e){globalThis.__hmBridge=null}
```

`typeof x !== 'undefined'` 不会抛异常，所以变量不存在时也不会出错。

通用脚本调用 `__hmBridge()` 就能拿到平台对象，进而接管 `playVideo`。

### 2.2 三类广告 API，返回形态不同

替换广告方法时**必须按返回形态分别处理**，否则会把调用方的链弄断：

| 形态 | 例子 | 替换成 |
|---|---|---|
| 返回 Promise | `playVideo(name)` → `.then(e => e > 0 ? 领奖 : ...)` | `Promise.resolve(1)` |
| 返回布尔 | `playVideo_pre()` → `if (pre) 跳过广告` | `return true` |
| 返回广告对象 | `createRewardedVideoAd()` → `ad.show().then(...)` | 返回 `{show, load, destroy, onClose...}`，其中 `show`/`load` 直接 resolve(1) |

第三种最容易被忽略：直接用 Promise 替换 `createRewardedVideoAd`，
调用方的 `ad.show()` 就不存在了，会直接抛异常。

### 2.3 globalThis 扫描

除了平台对象，标准小游戏 API 也在全局上：

```js
scanAds(G, 2, [])   // 深度 2 层，跳过 window/document/self/Laya 等
```

能接管到 `wx.createRewardedVideoAd`、`tt.createInterstitialAd` 这类。
扫描时必须带 `seen` 数组防环引用。

### 2.4 通用模式面板

未适配时只显示通用能力：

| 行 | 类型 | 说明 |
|---|---|---|
| 免广告 | `sw` | 开关，关掉就不再重新接管 |
| 接管强度 | `gear` | 浅/中/深 —— 对应扫描深度 1/2/3 |
| 重新接管广告 | 底部按钮 | 游戏可能自己重设方法，随时补一次 |

## 3. 模式自适应

注入发生在 **bundle 被编译之后、游戏执行之前**，那一刻 `__hmg` 还不存在。
所以模式不能一次性判定：

```js
G.__hmApplyMode = function () {
  var adapted = (G.__hmg && G.__hmg.playerInfo) ? 1 : 0;
  var mode = adapted ? 'adapted' : 'common';
  if (mode === G.__hmMode) return 0;
  G.__hmMode = mode;
  G.__hmLayout = null;      // 强制按新模式重建
  if (adapted) G.__hmSet = null;
  return 1;
};
```

探针的定时器每 1.2 秒调一次，返回 1 就丢掉旧面板重建。

## 4. 运行时脚本加载

native 层不再只认编译进 `.so` 的那一份：

```
/data/data/tv.danmaku.bili/files/hm_inject.js          ← 首选
/storage/emulated/0/Android/data/tv.danmaku.bili/files/hm_inject.js
/data/local/tmp/hm_inject.js
（都读不到 → 用编译期内嵌的 INJ_JS 兜底）
```

```c
static const char *load_runtime_script(void) {
    ...
    if (got < 256 || !strstr(b, "__hmw")) {   /* 坏文件直接跳过 */
        LOGI("runtime script %s rejected (no marker, %zu bytes)", PATHS[i], got);
        free(b);
        continue;
    }
    ...
}
```

**必须校验 `__hmw` 标记** —— 读到的文件如果被写坏，直接喂给 V8 会让游戏崩。
读不到就静默退回内嵌版本，不影响使用。

于是更新脚本的流程变成：

```
改 inj.js  →  放到 /data/data/tv.danmaku.bili/files/hm_inject.js  →  重启游戏
```

**不用重编译 `.so`，不用更新 App。**

## 5. App 拉取仓库

### 5.1 catalog.json

仓库根目录，游戏目录的唯一来源：

```json
{
  "version": 2,
  "updatedAt": "2026-11-01T20:50:00Z",
  "games": [
    {
      "id": "magic-realm",
      "name": "魔法领域",
      "engine": "Laya",
      "chapter": "第 10 章 驯兽师",
      "status": "full",
      "accent": "#2C6BED",
      "summary": "...",
      "features": ["..."],
      "scriptUrl": "https://raw.githubusercontent.com/.../scripts/hm_inject.js",
      "commonScriptUrl": "https://raw.githubusercontent.com/.../scripts/hm_common.js",
      "docsUrl": "https://github.com/..."
    }
  ]
}
```

`status` 三种：`full`（完整数值支持）/ `generic`（仅通用去广告）/ `planned`（计划中）。
App 据此显示不同的状态标签。

### 5.2 兜底链

```
GitHub raw  ┐
jsDelivr    ├─ 并行请求，取最先成功的
ghproxy     ┘
      ↓ 全失败
SharedPreferences 缓存
      ↓ 没有缓存
内置数据（BUILTIN）
```

三个远端源**并行**而不是串行 —— 串行最坏要等 3×8 秒。

界面上的「游戏目录」会显示当前用的是哪一级：`仓库 v2 · 2026-11-01` /
`本地缓存` / `内置数据`。

### 5.3 脚本更新按钮

游戏卡片里有「更新脚本」：

1. 下载 `scriptUrl` 到 App 私有目录，校验含 `__hmw`
2. `su -c` 部署到 `/data/data/tv.danmaku.bili/files/hm_inject.js`
3. 属主用**目标目录本身的 uid/gid** 对齐（Android toybox 的 `chown`
   不支持 `--reference`，而 bilibili 的 uid 是动态分配的，不能写死）
4. 部署失败时完整显示错误，并给出可长按复制的 adb 命令

## 6. 踩过的坑

### 6.1 `return@coroutineScope` 的值被丢弃

```kotlin
suspend fun load(context: Context): Catalog = withContext(Dispatchers.IO) {
    coroutineScope {
        for (d in pending) {
            ...
            return@coroutineScope parsed.copy(source = "remote")   // ← 白写
        }
    }
    readCache(context)?.copy(source = "cache") ?: Catalog(...)     // ← 永远走这里
}
```

`return@coroutineScope` 只是从 `coroutineScope` 的 lambda 返回，
而 `withContext` 用的是**块的最后一句表达式**。远端结果被整个丢掉了，
界面永远显示「本地缓存」。

**修法**：用变量把结果带出来。

### 6.2 漏了 INTERNET 权限

清单里没写 `<uses-permission android:name="android.permission.INTERNET" />`，
`HttpURLConnection` 全部失败，而且 `runCatching` 把异常吞掉，
表现只是「一直显示内置数据」——日志里什么都看不到。

**教训**：网络失败一定要打日志，别让 `runCatching` 把线索全埋了。

### 6.3 Android toybox 的 chown 不支持 --reference

```
chown: Unknown option 'reference=/data/...' (see "chown --help")
```

改用 `chown $(stat -c %u <目录>):$(stat -c %g <目录>) <文件>`，
拿目标目录自己的 uid/gid。

### 6.4 通用模式的改写门槛不能太松

改写源码是在 IIFE 函数体里插语句，**插错位置会让整个 bundle 语法错误、
游戏起不来**。所以通用模式要求三个条件同时满足：

- 体积 > 50KB（主 bundle 才这么大）
- 含 Laya 特征（`Laya.` 或 `laya.`）
- 含广告入口（`playVideo` / `createRewardedVideoAd` / `createInterstitialAd`）

已适配模式（命中 `playerInfo`）不受这个限制，因为它已经被实战验证过。
